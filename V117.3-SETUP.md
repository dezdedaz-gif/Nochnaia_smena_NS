# NS-05 V117.3 ONLINE + BACKEND

The client reads the public LootLocker leaderboard, but **all score writes are backend-only**. There is no direct client write fallback.

## Keys
- Game API key: public, placed in `netlb-config.js`.
- Server API key: secret, placed only in backend environment variable `LOOTLOCKER_SERVER_API_KEY`.

A real LootLocker key cannot be minted by the project itself. LootLocker issues keys in the owner's Web Console, so this release intentionally uses placeholders rather than a fake key.

## Backend
Deploy `server/` as an HTTPS Node 20 service. Use `render.yaml` or the Dockerfile.

Environment:
```text
LOOTLOCKER_SERVER_API_KEY=<real Server API key>
ALLOWED_ORIGIN=https://YOURNAME.itch.io
SCORE_BOARD=night_shift_score
TIME_BOARD=night_shift_time
GAME_VERSION=1.17.5.0
```

Health check: `GET /health`.

Then set `backendUrl` in `netlb-config.js` to the backend root URL. Keep `devMode: false` in production and replace the placeholder Game API key with your LIVE Game API key.

## LootLocker
Create/verify Player leaderboards `night_shift_score` and `night_shift_time`, with metadata enabled. For strict server-authoritative writes, disable Game API writes and let the backend be the only writer.


## V117.5 HARDENED+
Online submissions now require a server-issued per-night challenge. The gateway records the server start time, consumes the challenge after a successful submission, verifies completion, compares client time to server elapsed time, and rejects impossible score/time combinations.

## V118 security behavior
Keep `LOOTLOCKER_SERVER_API_KEY` only in Render secrets. The game sends periodic run telemetry to `/api/heartbeat`. If the gateway detects a suspicious run, it rejects the run and the game shows `ИЗВИНИ, НО НЕТ` instead of accepting the completion.
